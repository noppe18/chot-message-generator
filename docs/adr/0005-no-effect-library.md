# ADR-0005: Effect を採用せず、自前の軽量 `Result` 型で構成する

- 状態: 採用
- 日付: 2026-08-19

## 背景

本プロジェクトの要件に「なるべく関数型を意識した美しい設計と実装を心がける。不変性、純粋関数、副作用の局所化、テスト容易性を大切にする」がある。

同一作者の既存拡張 `noppe18.chotgit` は `effect` / `@effect/platform` / `@effect/platform-node` を実運用しており、Effect の採用は自然な選択肢だった。

Effect が本拡張にもたらすもの:

- 型付きエラー（`Effect<A, E, R>` の `E`）
- `Context` / `Layer` による依存注入
- `Fiber` による構造化された中断。VS Code の `CancellationToken` と対応付けられる
- リトライポリシー、リソース管理

## 決定

**Effect を採用しない。** `Result<T, E>` と判別可能ユニオンを自前で定義する（設計書 §5.1, §5.2）。依存は関数引数で注入する。

## 根拠

- **非同期の連鎖が浅い。** 本拡張の処理は「差分取得 → LLM 呼び出し → 注入」の一本道で、分岐は失敗時の早期リターンのみ。並行実行するものが無く、獲得・解放が必要なリソースも無い。Effect の真価が発揮される場面が構造的に存在しない。
- **中断は 1 箇所で済む。** キャンセルは `withProgress` が渡す `CancellationToken` を `sendRequest` にそのまま渡すだけで完結する。Fiber の抽象は要らない。
- **ランタイム依存ゼロを維持できる。** 本拡張は Effect 以外に依存パッケージを必要としない。Effect を入れると、この 1 つのためだけに数百 KB のバンドルが乗る。Marketplace 公開拡張として妥当なコストではない（[ADR-0002](./0002-no-proposed-api.md)）。
- **要件が求めているのは性質であって道具ではない。** 不変性は `readonly` 型で、純粋関数は `core/` から `vscode` を締め出すことで、副作用の局所化は adapter 層で、テスト容易性は引数注入で満たせる。`Result` 型 30 行でエラーの網羅性も型で保証できる。

## 帰結

- `core/result.ts` と `core/errors.ts` を自前で持つ。合わせて 50 行程度。
- `usecase` は `Deps` を第 1 引数で受け取る。テストでは plain object のフェイクを渡すだけで済み、モックライブラリも不要。
- エラーは `GenerationError` の判別可能ユニオンで表現し、UI 層の 1 箇所で文言へ写像する。`kind` を追加すると型検査が写像の漏れを検出する。
- 将来この拡張が育ち、並行処理や複雑なリトライが必要になった場合は本 ADR を再評価する。ただし `Result` ベースのコードは Effect へ移行しやすい形をしている（純粋関数は無変更、adapter だけが変わる）。

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| Effect を採用 | この規模・この処理形状に対して重い。バンドルサイズの対価に見合わない |
| `throw` と `try/catch` のみ | エラーの網羅性を型で保証できず、UI 層への写像を 1 箇所に集約する設計が崩れやすい |
| `neverthrow` などの小型 Result ライブラリ | 30 行で足りるものに依存を増やす理由がない |
